# Facturas (Facturar + Libro de facturas) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Section "2 · Facturas" becomes a menu with "Facturar" (pending delivery notes up to a date, grouped into one row per future invoice, issued all at once or one by one) and "Libro de facturas" (issued invoices between two dates, with their notes, print/email/delete).

**Architecture:** One new read endpoint (`GET /api/invoices/pending`) groups pending notes where the invoicing rules live; issuing reuses `POST /api/invoices/issue` once per row from the front. Two small additions to the invoice responses (`clientCode`, section `subtotal`). Front: `DataTable` gets an optional Enter and a scroll mode, a key-less `StaticTable` for the right-hand panels, and two screens built like `TaxList`/`DeliveryNoteRecord` (API calls injected as props so component tests use spies).

**Tech Stack:** Spring Boot 3.5 + Java 25 (`JAVA_HOME=C:\Program Files\Java\jdk-25.0.3`), MapStruct, JPA Specifications; SvelteKit 3, Svelte 5 runes, Tailwind 4 tokens, Vitest 4 browser mode, Playwright e2e on the packaged jar (port 18080).

**Spec:** `docs/superpowers/specs/2026-10-23-facturas-design.md`

## Global Constraints

- Work on the local branch `facturas`; implementers never commit or stage; the controller commits each task after review.
- Front paths relative to `front/`; API paths relative to `selfbill-api/src/`. Inside `src/lib` relative imports; outside `#lib/<path>.js`/`.svelte`; internal href/goto via `resolve()`; one `useKeys`/`keyLayer` per component (modal layers in their own component); "+" is `NumpadAdd`. Lucide icons imported one by one. Spanish UI texts exactly as the spec; English code and comments, matching the surrounding comment density.
- Money with `formatMoney` ("1.187,71 €"), rates with `formatPercent` ("4 %"), dates with `formatDate` (dd/mm/yyyy); API error texts only through `classifyError`/`showError` (`messages.ts`), never the API's English.
- Never start, stop or bind anything on port 8080 and never touch the user's `selfbill.db`/`~/.selfbill/secret.key`; temp APIs on another port with temp DB + key (see `front/e2e/serve-jar.mjs`). No python. Use the `codegraph_explore` MCP tool before grep/Read to locate code.
- Before running Maven: `export JAVA_HOME="/c/Program Files/Java/jdk-25.0.3"`. The IDE does not compile into `target/` (autobuild off).

## Review Focus

1. A second "+" or F3 (key repeat, double press) while issuing must not issue anything twice — Task 3 test `ignores keys while issuing`.
2. One row failing mid-batch must not stop the others; a lost connection must stop the batch at once — Task 3 tests `a failing row does not stop the rest`, `a lost connection stops the batch`.
3. Moving fast through the Libro must show the marked invoice's notes, never a late answer for an earlier row — Task 4 test `the panel ignores a late answer`.
4. A date typed but not loaded must never be invoiced — Task 3 test `editing the date empties the list`.
5. After issuing or deleting, the list reloads with the cursor at the same position (clamped) and the right panel follows it — Task 3 `F3 issues one row and keeps the cursor`, Task 4 `F8 deletes after confirming`.
